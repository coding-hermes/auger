# AUG-179 — make the AUG-176 corpus tests host-independent

Branch `wt/AUG-179` (base: origin/main `4a8cc94`). Commits: `bdebf44` (fix, hook
bypass disclosed), `831ce80` (per-project parametrization, hook bypass disclosed),
final evidence commit backed by `05-gate.log`.

## The defect

`test_shipped_blocks_are_verbatim_and_manifests_reconcile` asserted verbatim
containment against `source_abs` absolute paths recorded at conversion time
(`/home/kara/code-factory/specs/…`, `/home/kara/specs/coding-hermes-director/…`),
which exist on the authoring host only — CI run 43865562885 failed
`AssertionError: source vanished: /home/kara/code-factory/specs/ENVELOPE.md`
(and the same on 43865371784 @ 28f2477). The DATA was verified fine; the TEST's
portability was the defect.

## What shipped

1. **Portable digest leg (runs everywhere, CI included).**
   `scripts/ingest_markdown_specs.py` now records, per block,
   `text_sha256` = sha256 of the block's whitespace-normalized text **as emitted from
   the source span at conversion time** (never a self-hash of the emitted XML). The
   digest is committed in `corpora/*/manifest.json` together with a `digest_scheme`
   key. New test `test_shipped_block_digests_match_manifest` re-hashes every shipped
   block against its manifest digest; `validate_manifest` refuses any block whose
   `text_sha256` is missing or not 64-hex, so future conversions cannot silently drop
   the record. All three manifests regenerated with the converter; **every corpus XML
   is byte-identical** to before (`git diff` on `corpora/**/*.xml` is empty).
2. **Host containment leg (only where the sources exist).** The true containment
   assertion is unchanged, now per-project (parametrized), resolving each source in
   order: the `AUGER_SPEC_SOURCE_ROOTS` pin (authoritative when set — a missing pinned
   root is the CI simulation), the recorded absolute path, the manifest's declared
   `source_root`, then this repo's own tree for in-repo sources (the auger-docs corpus
   converts THIS repo's `docs/`, so a CI runner genuinely has it and its containment
   assertions run on CI too). When nothing resolves for a project, that project
   `pytest.skip`s with a NAMED reason (prints the missing root and states the digest
   leg covered integrity). No silent green.
3. **Coverage report regenerated by a real command.** New
   `scripts/gen_coverage_report.py` renders `docs/qa/aug176-conversion-coverage.md`
   from the committed manifests (with `--check`). Counts unchanged: 80 / 139 / 1027
   blocks, 0 skipped. The report gains a "Block integrity" line per corpus and now
   records the regenerating host path for auger-docs (see Residual).
4. `tests/gate.sh` arms untouched — `tests/test_spec_ingest.py` was already named in
   the pytest arm (verified, count 1) and the corpus loop unchanged.

## What the digest covers — and what it does not

- Covered, host-independent: the shipped XML matches, block for block, the text the
  converter emitted from the sources at conversion time (mutation → fail naming the
  block id; see `04-mutation.txt` [B]/[C]/[D3]).
- NOT covered without the real sources: that the CURRENT external source trees still
  agree with the corpus (the sources can drift after conversion). That remains the
  host leg's job (`03-containment.txt` [A]) and it still runs wherever the roots
  exist. On a CI host this half is, honestly, unmeasurable — that is exactly what the
  named skips say.
